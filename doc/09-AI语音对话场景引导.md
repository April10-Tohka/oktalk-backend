# 📄 PRD：儿童AI英语语音对话（场景引导式）

---

# 一、产品概述

## 1.1 产品名称

儿童AI英语 - 场景语音对话模块

---

## 1.2 产品目标

为儿童提供一个**低压力、可引导的英语口语练习环境**，通过模拟真实场景对话，让孩子：

* 敢开口说英语
* 学会基础表达
* 在对话中自然习得句型

---

## 1.3 产品定位

👉 **引导式英语对话（Guided Conversation）**

区别于：

* ❌ 自由聊天（不可控）
* ❌ 语音评测（高压力）

---

# 二、核心设计原则

---

## 2.1 流程控制原则

```text
是否进入下一Step → 规则控制（确定性）
语言表达生成 → LLM生成（自然性）
```

---

## 2.2 儿童体验原则

* 不强调错误（No “Wrong”）
* 鼓励优先（Encouragement First）
* 不阻塞流程（No Dead End）
* 教学优先（Teach > Test）

---

## 2.3 系统架构原则

```text
ASR（语音识别） → 规则判断 → LLM生成 → TTS（语音合成）
```

## 5.1 规则判断（主逻辑）

---

### 5.1.1 判断方法（MVP）

```go
func match(userText string, expected []string) bool {
    userText = strings.ToLower(userText)
    for _, e := range expected {
        if strings.Contains(userText, e) {
            return true
        }
    }
    return false
}
```

### 4.3 StartSession

```
逻辑：
1. sceneLoader.GetByID(sceneID) → 不存在返回 400 "场景不存在"

2. sessionRepo.FindActiveByUserAndScene(userID, sceneID)
   - 存在（断点续学）：
       取 current_step，找到对应 step 配置
       is_resumed = true
   - 不存在（新建）：
       生成 UUID，INSERT scene_sessions（current_step=1, status=active）
       is_resumed = false
       step = steps[0]

3. 调用 TTS 合成 step.QuestionAudioText
   上传到 OSS → question_audio_url
   TTS/OSS 失败 → question_audio_url = ""（不阻断流程）

4. 返回 session_id、is_resumed、current_step 信息
```

### 4.4 SubmitAnswer（核心）

```
逻辑：

步骤 1：参数校验
  session_id、step_id 非空
  audio_file 非空且 ≤ 10MB

步骤 2：查询并验证 session
  sessionRepo.FindByID(session_id)
  不存在 → 404
  session.UserID != 当前用户 → 403
  session.Status != "active" → 400 "场景已完成"
  session.CurrentStep != step_id → 400 "步骤不匹配"

步骤 3：获取场景和步骤配置
  sceneLoader.GetStep(session.SceneID, step_id)
  不存在 → 500（数据异常）

步骤 4：查询本 step 已尝试次数
  attempt = messageRepo.CountAttempts(session_id, step_id) + 1

步骤 5：ASR 识别
  调用 asrProvider.RecognizeAudio(audioData, format, sampleRate)
  失败 → 返回 500
  user_text 为空 → 返回 400 "音频为空，请重新录音"

步骤 6：上传用户音频到 OSS（异步，失败只记日志）
  go func() { ossClient.Upload(audioData, "scene/{session_id}/user_{uuid}.wav") }()

步骤 7：判断逻辑

  7.1 规则判断：
    userTextLower = strings.ToLower(user_text)
    for _, e := range step.Expected:
        if strings.Contains(userTextLower, e) → match_result = "rule_pass"，跳到步骤 8

  7.2 规则未命中 → LLM 语义判断：
    构建 prompt（见 Prompt 设计章节的语义判断 prompt）
    调用 llmProvider（强制 JSON 输出）
    解析 {"semantic_match": true/false}
    true  → match_result = "llm_pass"，跳到步骤 8
    false → match_result = "fail"

步骤 8：LLM 生成回复
  根据 match_result 和 attempt 动态构建 System Prompt：
    rule_pass / llm_pass           → 表扬 prompt
    fail && attempt == 1           → 鼓励 prompt（不给答案）
    fail && attempt >= 2           → 示范 prompt（给出答案）

  调用 llmProvider，强制输出 JSON：
  {"status":"pass"|"fail","reply":"...","hint":"...（可选）","expand":"...（可选）"}

  解析失败（LLM 输出非法 JSON）→ 使用 fallback：
    pass: {"status":"pass","reply":"Great job! Let's continue!"}
    fail: {"status":"fail","reply":"Good try! Let's try again!","hint":"Say: "+step.Expected[0]}

步骤 9：TTS 合成 reply 文本
  调用 ttsProvider.Synthesize(llmReply.Reply)
  上传到 OSS → ai_audio_url
  失败 → ai_audio_url = ""（不阻断）

步骤 10：判断是否推进 Step
  should_advance:
    match_result == "rule_pass" 或 "llm_pass" → true
    match_result == "fail" && attempt == 1     → false（还有一次机会）
    match_result == "fail" && attempt >= 2     → true（强制推进）

步骤 11：处理推进逻辑
  if should_advance:
    totalSteps = len(scene.Steps)
    isLastStep = (step_id == totalSteps)

    if isLastStep:
      sessionRepo.UpdateStatus(session_id, "completed")
      scene_completed = true
      next_step = nil
    else:
      nextStepID = step_id + 1
      sessionRepo.UpdateCurrentStep(session_id, nextStepID)
      nextStep = sceneLoader.GetStep(sceneID, nextStepID)
      TTS 合成 nextStep.QuestionAudioText → next_question_audio_url（失败置空）
      scene_completed = false

步骤 12：异步写 scene_messages 记录
  go func() {
    messageRepo.Create({
      id, session_id, user_id, scene_id, step_id,
      attempt, user_text, user_audio_url,
      match_result, ai_reply_text, ai_audio_url,
      llm_status, step_advanced=should_advance
    })
  }()

步骤 13：返回响应
```

## 九、代码约束

1. **分层严格**：Handler 只做参数绑定和响应，业务逻辑全部在 Service，数据库操作全部在 Repository
2. **复用现有 ASR/LLM/TTS 接口**：调用现有 domain 接口方法，不重新实现第三方调用，如果domain定义的接口方法无法实现功能留下个todo注释并mock数据来继续主流程，我自己来实现解决todo。
3. **LLM 输出解析要有 fallback**：JSON 解析失败时使用预设的 fallback 文本，不让解析错误中断流程
4. **异步写消息记录**：`messageRepo.Create` 在独立 goroutine 中执行，失败只记日志，不影响主流程响应
5. **TTS/OSS 失败不阻断**：TTS 合成或 OSS 上传失败时，对应 URL 字段置为空字符串，主流程继续
6. **场景配置只读一次**：`SceneLoader` 在服务启动时加载所有配置到内存，运行时不重复读文件
7. **attempt 并发安全**：`CountAttempts` 查数据库取得已有次数，加 1 得到本次 attempt，不使用内存计数
8. **不修改现有代码**：不改动现有 handler、service、repository、model 文件，只新增文件
9.**检查代码**： 使用go build来检查代码的语法正确性和依赖完整性。
