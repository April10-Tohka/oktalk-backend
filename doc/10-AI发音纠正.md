# 一、产品概述

---

## 🎯 产品定位

AI发音纠正模块是一个**面向儿童的英语发音训练系统**，通过：

* 语音评测（评分）
* AI反馈（纠错 + 鼓励）
* 重复练习机制

帮助用户提升英语发音准确度。

---

## 🧠 核心理念

```text id="f3ny7l"
不是“测一次”，而是“练到更好”
```

---

---

# 二、产品目标

---

## 🎯 核心目标

* 提升发音准确率（Accuracy）
* 提高重复练习率
* 建立结构化学习路径（Unit）

---

## 📊 关键指标（MVP）

* Unit完成率 ≥ 80%
* 重复练习率 ≥ 60%
* 单Unit平均尝试次数 ≥ 5次

```go
package config

// PronunciationUnitConfig 单个 Unit 的完整配置
type PronunciationUnitConfig struct {
    ID         string                  `json:"id"`
    Type       string                  `json:"type"`    // "word" / "sentence"
    Topic      string                  `json:"topic"`   // "food" / "fruits" / "animals" / "greeting" 等
    Title      string                  `json:"title"`
    CoverEmoji string                  `json:"cover_emoji"`
    Items      []PronunciationItem     `json:"items"`
}

// PronunciationItem Unit 中的单个练习项
type PronunciationItem struct {
    ID               int    `json:"id"`
    Content          string `json:"content"`           // 单词或句子原文
    StandardAudioURL string `json:"standard_audio_url"` // 提前合成的标准发音 OSS URL
}
```

```go
// PronunciationLoader 从配置文件目录加载所有 Unit
```

## 二、数据库设计

新增两张表，**不修改现有表**。

### 2.1 pronunciation_sessions 表（Unit 会话 / 断点续学）

```sql
CREATE TABLE pronunciation_sessions (
    id            VARCHAR(36)  NOT NULL PRIMARY KEY COMMENT '主键UUID',
    user_id       VARCHAR(36)  NOT NULL              COMMENT '用户ID',
    unit_id       VARCHAR(50)  NOT NULL              COMMENT 'Unit ID，对应配置文件',
    current_index INT          NOT NULL DEFAULT 1    COMMENT '当前练到第几个item（从1开始）',
    status        VARCHAR(20)  NOT NULL DEFAULT 'ongoing'
                                                    COMMENT '状态: ongoing/finished',
    created_at    TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at    TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP
                               ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_user_id (user_id),
    INDEX idx_unit_status (unit_id, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='发音训练会话表（断点续学）';
```

### 2.2 pronunciation_records 表（每次评测记录）

```sql
CREATE TABLE pronunciation_records (
    id              VARCHAR(36)   NOT NULL PRIMARY KEY COMMENT '主键UUID',
    session_id      VARCHAR(36)   NOT NULL              COMMENT '关联 pronunciation_sessions.id',
    user_id         VARCHAR(36)   NOT NULL              COMMENT '用户ID',
    unit_id         VARCHAR(50)   NOT NULL              COMMENT 'Unit ID',
    item_id         INT           NOT NULL              COMMENT '练习项ID',
    content         VARCHAR(500)  NOT NULL              COMMENT '练习的单词或句子',
    practice_type   VARCHAR(20)   NOT NULL              COMMENT 'word / sentence',

    -- 评测结果
    raw_score       DECIMAL(3,1)  NOT NULL              COMMENT '科大讯飞原始分 0.0-5.0',
    stars           INT           NOT NULL              COMMENT '星星数 0-5（四舍五入）',
    problem_words   JSON                                COMMENT '有发音问题的词列表 ["pork","chicken"]',

    -- 用户音频
    user_audio_url  VARCHAR(500)                        COMMENT '用户录音 OSS URL',

    -- AI 反馈
    ai_encourage    TEXT                                COMMENT 'LLM 生成的鼓励语',
    ai_problem_tip  TEXT                                COMMENT 'LLM 生成的问题提示',
    ai_suggestion   TEXT                                COMMENT 'LLM 生成的建议',
    ai_audio_url    VARCHAR(500)                        COMMENT 'TTS 合成的反馈音频 OSS URL',

    created_at      TIMESTAMP     NOT NULL DEFAULT CURRENT_TIMESTAMP,

    INDEX idx_session_item  (session_id, item_id),
    INDEX idx_user_unit     (user_id, unit_id),
    INDEX idx_created_at    (created_at)
```

### 3.3 开始或续学 Unit

```
POST /api/v1/pronunciation/session/start
```

**Request Body**
```json
{
  "unit_id": "word_food"
}
```

**服务端逻辑**
```
1. 校验 unit_id 对应配置是否存在，不存在 → 400

2. 查询该用户是否有同 unit_id 的 ongoing 会话：
   - 存在 → 断点续学，is_resumed=true
   - 不存在 → 新建 pronunciation_sessions（current_index=1, status=ongoing）

3. 根据 current_index 取对应 item 配置

4. 返回会话信息和当前练习项
```

**Response 200**

### 3.4 提交录音评测（核心接口）

```
POST /api/v1/pronunciation/evaluate
Content-Type: multipart/form-data
```

**Request 参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| session_id | string | 是 | 会话 ID |
| item_id | int | 是 | 当前练习项 ID |
| audio_file | file | 是 | 用户录音，≤10MB |

**完整服务端逻辑**

```
步骤 1：参数校验
  session_id、item_id 非空
  audio_file 非空且 ≤ 10MB

步骤 2：验证会话
  查询 pronunciation_sessions，验证：
  - 存在且属于当前用户，否则 404/403
  - status == "ongoing"，否则 400 "Unit已完成"

步骤 3：获取 item 配置
  pronunciationLoader.GetItem(session.UnitID, item_id)
  不存在 → 500

步骤 4：调用科大讯飞发音评测
  传入 audio_file + content + practice_type
  返回：
  - total_score（0.0-5.0 浮点）
  - 每个词的 score 和 DpMessage

步骤 5：处理评测结果
  stars = round(total_score)（四舍五入，范围 0-5）
  problem_words = 所有 DpMessage != 0 的词列表

步骤 6：上传用户音频到 OSS（异步，失败只记日志）
  go func() { ossClient.Upload(audioData, "pronunciation/{session_id}/{item_id}_{uuid}.wav") }()

步骤 7：构建 LLM 输入并调用
  input = {
    practice_type,
    content,
    total_score,
    stars,
    problem_words
  }
  调用 LLM（强制 JSON 输出）
  解析输出：{ encourage, problem_tip, suggestion }
  解析失败 → fallback：
    stars >= 4: { encourage: "Great job! 🌟", problem_tip: "Everything sounds great!", suggestion: "Keep it up!" }
    stars < 4:  { encourage: "Good try! 💪", problem_tip: "Let's practice more!", suggestion: "Listen and try again! 🎧" }

步骤 8：TTS 合成 AI 反馈音频
  合成文本 = encourage + " " + problem_tip + " " + suggestion
  上传到 OSS → ai_audio_url
  失败 → ai_audio_url = ""（不阻断）

步骤 9：异步写 pronunciation_records
  go func() {
    recordRepo.Create({
      id, session_id, user_id, unit_id, item_id,
      content, practice_type,
      raw_score, stars, problem_words,
      user_audio_url, ai_encourage, ai_problem_tip,
      ai_suggestion, ai_audio_url
    })
  }()

步骤 10：判断是否推荐进入下一项
  recommend_advance = (raw_score >= 3.75)

步骤 11：返回响应
```

### 3.5 推进到下一个 item

```
POST /api/v1/pronunciation/session/advance
```

**设计说明**

评测和推进拆成两个独立接口，原因是：用户可能在看完反馈后选择再练一次，也可能直接点"下一条"，推进动作由用户主动触发，不在评测时自动发生。

**Request Body**
```json
{
  "session_id": "uuid",
  "current_item_id": 1
}
```

**服务端逻辑**
```
1. 验证 session 存在且属于当前用户
2. 验证 current_item_id == session.current_index（防止重复推进）
3. 取 unit 配置，判断是否是最后一个 item：
   - 不是最后一个：
       current_index + 1
       UPDATE pronunciation_sessions SET current_index = ?
       返回下一个 item 信息
   - 是最后一个：
       UPDATE pronunciation_sessions SET status = "finished"
       返回 unit_completed = true
```

**Response 200（中间项推进）**
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "session_id": "uuid",
    "unit_completed": false,
    "next_item": {
      "id": 2,
      "content": "chicken",
      "standard_audio_url": "https://oss.example.com/pronunciation/standard/chicken.mp3",
      "item_index": 2,
      "total_items": 3,
      "is_last": false
    }
  }
}
```

**Response 200（最后一项推进，Unit 完成）**
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "session_id": "uuid",
    "unit_completed": true,
    "next_item": null
  }
}
```

### 3.6 获取 Unit 完成总结

```
GET /api/v1/pronunciation/session/:session_id/summary
```

**服务端逻辑**
```
1. 验证 session 存在且属于当前用户
2. status != "finished" → 400 "Unit未完成"
3. 查询该 session 下所有 pronunciation_records
4. 按 item_id 分组，每组取 max(raw_score) 作为该 item 最高分
5. 计算平均分 = sum(最高分) / item 总数
6. 换算平均星星数 = round(平均分)
7. 构建 LLM 输入，调用 LLM 生成总结文本
8. 返回总结
```

**LLM 总结输入**
```json
{
  "items": [
    { "content": "pork",    "best_score": 4.0 },
    { "content": "chicken", "best_score": 3.2 },
    { "content": "beef",    "best_score": 4.5 }
  ],
  "average_score": 3.9
}
```

**LLM 总结输出**
```json
{
  "summary": "Great job! 🎉 You did really well on beef and pork. Let's keep practicing chicken!",
  "highlight": ["beef", "pork"],
  "weak": ["chicken"]
}
```

### 5.2 StartSession

```
逻辑：
1. loader.GetByID(unitID) → 不存在返回 400 "Unit不存在"

2. sessionRepo.FindOngoingByUserAndUnit(userID, unitID)
   - 存在（断点续学）：is_resumed=true，取 current_index
   - 不存在：生成 UUID，INSERT pronunciation_sessions，is_resumed=false，current_index=1

3. loader.GetItem(unitID, current_index) → 取当前 item

4. 返回 session_id、is_resumed、current_item 信息
   current_item 包含：id, content, standard_audio_url,
   item_index=current_index, total_items, is_last=(current_index==total_items)
```

### 5.3 Evaluate（核心）

```
逻辑：

步骤 1：参数校验
  session_id、item_id 非空
  audio_file 非空且 ≤ 10MB（10 * 1024 * 1024 字节）

步骤 2：验证会话
  sessionRepo.FindByID(session_id)
  不存在 → 404
  session.UserID != 当前用户 → 403
  session.Status != "ongoing" → 400 "Unit已完成"

步骤 3：获取 item 配置
  loader.GetItem(session.UnitID, item_id) → 不存在返回 500

步骤 4：调用科大讯飞发音评测
  参照现有 EvaluationProvider 接口的调用方式
  传入：audio_file 的字节数据、item.Content、practice_type
  失败 → 返回 500 "评测服务异常"

步骤 5：处理评测结果
  raw_score = 科大讯飞返回的总分（float32，0.0-5.0）
  stars = int(math.Round(float64(raw_score)))  // 四舍五入，范围 0-5
  problem_words = 遍历每个词，收集 DpMessage != 0 的词文本，构成 []string
  // DpMessage 字段名以现有 EvaluationProvider 返回结构体的实际字段名为准

步骤 6：上传用户音频到 OSS（异步，失败只记日志）
  go func() {
      url, err := ossClient.Upload(audioData,
          fmt.Sprintf("pronunciation/%s/%d_%s.wav", session_id, item_id, uuid))
      if err != nil {
          logger.Warn("upload user audio failed", "error", err)
          return
      }
      // url 存入局部变量供后续写库使用
      // 注意：异步上传时需要用 channel 或先同步上传再异步写库
      // 建议：先同步上传获得 URL，再异步写 pronunciation_records
  }()
  // 实际建议：同步上传获得 user_audio_url，上传失败置为""，不阻断主流程

步骤 7：构建 LLM 输入并调用
  promptData = {
      practice_type: item.Type（从 unit config 取）,
      content: item.Content,
      total_score: raw_score,
      stars: stars,
      problem_words: problem_words（[]string，空列表表示无问题）
  }

  System Prompt（固定）：
  "你是一位儿童英语发音老师，说话简短活泼，多用 emoji，语气鼓励正向。
  只能返回 JSON，不允许返回任何其他内容。"

  User Prompt（动态拼接）：
  fmt.Sprintf(`小朋友正在练习英语发音。
  练习内容：%s（%s）
  总体评分：%.1f/5，对应%d颗星
  有发音问题的词：%v（空列表表示全部正确）

  请生成一段发音反馈，只返回如下 JSON：
  {"encourage":"鼓励语，一句话，10词以内","problem_tip":"问题提示，一句话；无问题词时写 Everything sounds great!","suggestion":"建议，一句话，简单可操作"}`,
  item.Content, practiceType, raw_score, stars, problem_words)

  调用 llmProvider，解析返回的 JSON
  解析失败 → 使用 fallback：
    stars >= 4: { encourage:"Great job! 🌟", problem_tip:"Everything sounds great!", suggestion:"Keep it up!" }
    stars < 4:  { encourage:"Good try! 💪",  problem_tip:"Let's practice more!",      suggestion:"Listen and try again! 🎧" }

步骤 8：TTS 合成 AI 反馈音频
  合成文本 = encourage + " " + problem_tip + " " + suggestion
  调用 ttsProvider.Synthesize(合成文本)
  上传到 OSS → ai_audio_url
  失败 → ai_audio_url = ""（不阻断）

步骤 9：异步写 pronunciation_records
  go func() {
      recordRepo.Create(ctx, &model.PronunciationRecord{
          ID: uuid, SessionID: session_id, UserID: user_id,
          UnitID: session.UnitID, ItemID: item_id,
          Content: item.Content, PracticeType: practiceType,
          RawScore: raw_score, Stars: stars,
          ProblemWords: JSON序列化(problem_words),
          UserAudioURL: user_audio_url,
          AIEncourage: llmResult.Encourage,
          AIProblemTip: llmResult.ProblemTip,
          AISuggestion: llmResult.Suggestion,
          AIAudioURL: ai_audio_url,
      })
  }()

步骤 10：判断是否推荐进入下一项
  recommend_advance = (raw_score >= 3.75)

步骤 11：返回响应
  {
    session_id, item_id, content,
    evaluation: { raw_score, stars, problem_words },
    ai_feedback: { encourage, problem_tip, suggestion, audio_url },
    recommend_advance
  }
```

### 5.4 Advance

```
逻辑：
1. sessionRepo.FindByID(session_id)
   不存在 → 404
   UserID 不匹配 → 403
   status != "ongoing" → 400 "Unit已完成"

2. session.CurrentIndex != current_item_id → 400 "步骤不匹配"

3. loader.GetByID(session.UnitID) 取 unit 配置
   totalItems = len(unit.Items)
   isLast = (current_item_id == totalItems)

4. if isLast:
     sessionRepo.UpdateStatus(session_id, "finished")
     返回 { unit_completed: true, next_item: null }
   else:
     nextIndex = current_item_id + 1
     sessionRepo.UpdateCurrentIndex(session_id, nextIndex)
     nextItem = loader.GetItem(session.UnitID, nextIndex)
     返回 {
       unit_completed: false,
       next_item: {
         id, content, standard_audio_url,
         item_index: nextIndex,
         total_items: totalItems,
         is_last: (nextIndex == totalItems)
       }
     }
```

### 5.5 GetSummary

```
逻辑：
1. sessionRepo.FindByID(session_id)
   不存在 → 404
   UserID 不匹配 → 403
   status != "finished" → 400 "Unit未完成，无法查看总结"

2. loader.GetByID(session.UnitID) 取 unit 配置

3. recordRepo.GetBestScorePerItem(session_id)
   返回 map[itemID]bestScore

4. 遍历 unit.Items，按顺序构建 items 列表：
   每个 item：{ content, best_score: map中取值（不存在则0）, best_stars: round(best_score) }

5. average_score = sum(all best_score) / len(items)（保留一位小数）
   average_stars = round(average_score)

6. 构建 LLM 总结输入并调用：

   System Prompt（固定）：
   "你是一位儿童英语发音老师，说话简短活泼，多用 emoji，语气鼓励正向。
   只能返回 JSON，不允许返回任何其他内容。"

   User Prompt：
   fmt.Sprintf(`小朋友完成了一组英语发音练习，以下是每个内容的最佳得分：
   %s
   平均分：%.1f/5

   请生成练习总结，只返回如下 JSON：
   {"summary":"总结语，两句话以内，鼓励为主","highlight":["发音较好的内容列表"],"weak":["需加强的内容列表，无则为空数组"]}`,
   JSON序列化(items_for_llm), average_score)

   // items_for_llm 格式：[{"content":"pork","best_score":4.0}, ...]

   解析失败 → fallback：
   { summary: "Great effort! 🎉 Keep practicing every day!", highlight: [], weak: [] }

7. 返回完整总结
```

## 八、代码约束

1. **分层严格**：Handler 只做参数绑定和响应，业务逻辑全部在 Service，数据库操作全部在 Repository
2. **复用现有接口**：科大讯飞、LLM、TTS、OSS 全部调用现有 domain 接口和封装，不重新实现.如果domain定义的接口方法无法实现功能留下个todo注释并mock数据来继续主流程，我自己来实现解决todo。
3. **DpMessage 字段名以实际为准**：扫描现有科大讯飞返回结构体，找到标识发音问题的字段，不假设字段名
4. **LLM 输出解析要有 fallback**：JSON 解析失败时使用预设 fallback，不让解析错误中断主流程
5. **异步写记录**：`recordRepo.Create` 在独立 goroutine 中执行，失败只记 warn 日志，不影响响应
6. **TTS/OSS 失败不阻断**：失败时对应 URL 置为空字符串，主流程继续
7. **配置只读一次**：`PronunciationLoader` 在服务启动时加载到内存，运行时不重复读文件
8. **stars 计算用 math.Round**：`import "math"`，`stars = int(math.Round(float64(rawScore)))`，结果 clamp 到 0-5
9. **不修改现有代码**：只新增文件，不改动现有任何 handler、service、repository、model 文件
