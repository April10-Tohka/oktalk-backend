# 【阶段 5：AI 语音对话模块核心流程伪代码】

---

## 一、接口：POST /api/v1/chat/submit

**功能**：用户上传语音文件，后端异步处理 ASR + LLM + TTS，返回任务 ID

**流程类型**：同步 API + 异步任务处理

---

### 1.1 伪代码流程

```
流程：POST /api/v1/chat/submit
├─ 【同步阶段】
│  ├─ 步骤 1：接收 HTTP 请求
│  │  ├─ 参数：audio_file（文件，必填）、conversation_id（字符串，必填）、conversation_type（字符串，可选）、difficulty_level（字符串，可选）、topic（字符串，可选）
│  │  │         
│  │  └─ 异常点：文件为空 → 返回 400 Bad Request
│  │
│  ├─ 步骤 2：身份验证
│  │  ├─ 从 HTTP Header 获取 Authorization Token
│  │  ├─ 调用 TokenService.ValidateToken(token)
│  │  └─ 异常点：Token 无效或过期 → 返回 401 Unauthorized
│  │
│  ├─ 步骤 3：提取用户 ID
│  │  ├─ user_id = Token.解析并获取(user_id)
│  │  └─ 异常点：Token 中缺少 user_id → 返回 401
│  │
│  ├─ 步骤 4：参数校验
│  │  ├─ 检查 audio_file 是否为空
│  │  │  └─ 异常点：为空 → 返回 400 参数错误
│  │  ├─ 检查 audio_file 大小 ≤ 10MB
│  │  │  └─ 异常点：超过限制 → 返回 400
│  │  └─ 检查 conversation_id 是否为空
│  │     └─ 异常点：为空 → 返回 400（conversation_id 必须由 /session/start 接口预先创建）
│  │
│  ├─ 步骤 5：处理默认参数
│  │  ├─ 如果 conversation_type 为空 → 设置为 "free_talk"
│  │  ├─ 如果 difficulty_level 为空 → 设置为 "beginner"
│  │  ├─ 如果 topic 为空 → 设置为 "general"
│  │
│  ├─ 步骤 6：速率限制检查
│  │  ├─ 调用 RateLimiter.CheckLimit(user_id, "chat_submit", 限制=10/分钟)
│  │  └─ 异常点：超过限制 → 返回 429 Too Many Requests
│  │
│  │
│  ├─ 步骤 7：验证会话是否存在（conversation_id 必须对应已创建的会话）
│  │  ├─ 调用 Cache.GetChatSession(ctx, conversation_id)
│  │  ├─ 如果缓存未命中：
│  │  │  ├─ 调用 ChatRepository.GetSession(ctx, user_id, conversation_id)
│  │  │  ├─ 异常点：数据库查询失败 → 返回 500
│  │  │  └─ 如果数据库中也不存在该会话 → 返回 404 会话不存在
│  │  └─ 如果存在：
│  │     └─ 继续（会话由 /session/start 事先创建，这里只做校验）
│  │
│  ├─ 步骤 8：生成任务 ID
│  │  ├─ task_id = fmt.Sprintf("%s_%d", task.Type, time.Now().UnixNano())
│  │  
│  │
│  ├─ 步骤 9：创建初始任务状态记录
│  │  ├─ 构建任务对象task：
│  │  │  ├─ id
│  │  │  ├─ type = "chat"
│  │  │  ├─ status = "pending"
│  │  │  ├─ user_id
│  │  │  ├─ created_at = now
│  │  │  ├─ retry_count = 0
│  │  │  └─ payload
│  │
│  ├─ 步骤 10：将任务对象task推送到Worker Pool
│  │  ├─ 调用 Manager.SubmitTask(ctx,task)
│  │  │  └─ 异常点：队列满 → 返回 503
│  │  └─ 验证推送成功 → 检查返回值
│  │
│  ├─ 步骤 11：更新用户学习进度（原子操作）
│  │  ├─ 调用 Cache.IncrDailyProgress(ctx,user_id, today_date, "chat_submission_count", 1)
│  │  └─ 异常点：Redis 操作失败 → 记录但不中断
│  │
│  ├─ 步骤 12：构建响应体
│  │  ├─ 响应结构：
│  │  │  ├─ code = 200
│  │  │  ├─ message = "success"
│  │  │  └─ data = {
│  │  │      task_id: task_id,
│  │  │      conversation_id: conversation_id,
│  │  │      status: "pending",
│  │  │      message: "语音对话任务已提交，请轮询查询结果"
│  │  │    }
│  │  └─ HTTP 状态码：200 OK
│  │
│  └─ 步骤 13：返回响应
│     └─ 返回 JSON 响应给客户端
│
├─ 【异步阶段】（由 Worker Pool 处理，不阻塞主流程）
│  │
│  ├─ Worker goroutine 从channel中拉取任务
│  │  ├─ 调用 processTask处理任务
│  │  
│  │
│  ├─ 步骤 A1：ASR 语音识别（异步）
│  │  ├─ 更新任务状态：status = "processing", current_stage = "asr"
│  │  ├─ 读取音频文件
│  │  │  └─ 异常处理：读取失败 → status = "failed", error = "音频读取失败"
│  │  │ 
│  │  ├─ 调用 ASR 
│  │  │  ├─ 异常处理：
│  │  │  │  ├─ 超时 → 重试 3 次（指数退避）
│  │  │  │  ├─ API 错误 → status = "failed", error = API 错误信息
│  │  │  │  └─ 网络错误 → 重试 3 次
│  │  │  └─ 返回：user_text（识别的文本）
│  │
│  ├─ 步骤 A2：LLM 对话生成（异步）
│  │  ├─ 更新任务状态： current_stage = "llm"
│  │  ├─ 获取对话历史（用于上下文）
│  │  │  ├─ 调用 Cache.GetChatHistory(user_id, conversation_id, limit=10)
│  │  │  ├─ 如果没有缓存 → 调用 Database.GetChatHistory(user_id, conversation_id, limit=10)
│  │  │  └─ 异常处理：查询失败 → 使用空历史继续
│  │  ├─ 构建 LLM 请求上下文
│  │  │  ├─ 系统提示词（System Prompt）
│  │  │  ├─ 对话历史（Chat History）
│  │  │  ├─ 当前用户输入（user_text）
│  │  │  ├─ 话题约束（topic ）
│  │  │  
│  │  ├─ 调用 LLM 
│  │  │  ├─ 异常处理：
│  │  │  │  ├─ 超时 → 使用 fallback 回复（"我没有听清，请重新说"）
│  │  │  │  ├─ API 错误 → status = "failed", error = "AI 生成失败"
│  │  │  │  └─ 速率限制 → 重试 3 次（指数退避）
│  │  │  └─ 返回：ai_text（AI 生成的回复）
│  │  ├─ 验证生成结果
│  │  │  ├─ 检查长度：0 < len(ai_text) ≤ 30 字符
│  │  │  └─ 异常处理：
│  │  │     ├─ 长度不合法 → status = "failed", error = "AI 生成回复长度异常"
│  │  │     └─ 其他异常 → 记录日志，status = "failed", error = "AI 生成回复异常"
│  │
│  ├─ 步骤 A3：TTS 语音合成（异步）
│  │  ├─ 更新任务状态： current_stage = "tts"
│  │  ├─ 调用 TTS 
│  │  │  ├─ 异常处理：
│  │  │  │  ├─ 超时 → 重试 2 次
│  │  │  │  ├─ 文本过长 → 截断后重新合成
│  │  │  │  └─ API 错误 → status = "failed", error = "语音合成失败"
│  │  │  └─ 返回：audio_data（音频二进制数据）
│  │
│  │
│  ├─ 步骤 A5：上传 AI 语音，用户语音到 OSS
│  │  ├─ 上传 AI 语音，用户语音到 OSS
│  │  │  ├─ 生成文件名：fmt.Sprintf("chat/%s/ai_%s.mp3", conversationID, aiMsgID)、fmt.Sprintf("chat/%s/user_%s.%s", conversationID, userMsgID, audioType)
│  │  │  ├─ 调用 OSS.Upload(audio_data, 文件路径)
│  │  │  └─ 异常处理：上传失败 → 记录日志
│  │  └─ userAudioURL、aiAudioURL = OSS 返回的 URL
│  │
│  ├─ 步骤 A6：保存对话记录到数据库VoiceConversation、ConversationMessage
│  │  ├─ 构建对话记录对象：
│  │  │  ├─ user_id
│  │  │  ├─ conversation_id
│  │  │  ├─ turn（对话轮数，从数据库查询递增）
│  │  │  ├─ user_text
│  │  │  ├─ user_audio_url
│  │  │  ├─ ai_text
│  │  │  ├─ ai_audio_url
│  │  │  ├─ created_at
│  │  │  └─ feedback_rating（初始为 null）
│  │  ├─ 调用 Database.InsertChatRecord(对话记录)
│  │  └─ 异常处理：数据库写入失败 → 重试 3 次，最终失败记录日志
│  │
│  ├─ 步骤 A7：更新学习进度统计
│  │  ├─ 调用 Cache.IncrDailyProgress(user_id, today_date, "chat_completion_count", 1)
│  │  ├─ 调用 Cache.IncrDailyProgress(user_id, today_date, "total_chat_duration_ms", audio_duration_ms)
│  │  └─ 异常处理：Redis 失败 → 记录但不中断任务
│  │
│  ├─ 步骤 A8：更新任务最终状态
│  │  ├─ 更新 Redis 中的任务状态：
│  │  │  ├─ status = "success"
│  │  │  ├─ current_stage = "completed"
│  │  │  ├─ updated_at = now
│  │  │  └─ TTL 设置为 24 小时（用户可查询 24 小时内的结果）
│  │  ├─ Redis 缓存AI语音对话结果：
│  │  │  ├─ 键：chat:result:{conversation_id}
│  │  │  ├─ 值：ChatResult 结构体（包含 user_text, ai_text, user_audio_url, ai_audio_url, created_at）
│  │  │  └─ TTL 设置为 24 小时（用户可查询 24 小时内的结果）
│  │  ├─ 同时写入数据库（异步）
│  │  └─ 异常处理：更新失败 → 记录日志
│  │
│  │
│  └─ 异步任务完成
│
└─ 流程结束
```

### 1.2 异常处理总结

| 异常点 | 阶段 | 处理方式 | 用户感知 |
|--------|------|---------|---------|
| 文件为空 | 同步 | 返回 400 | 参数错误提示 |
| Token 无效 | 同步 | 返回 401 | 需要重新登录 |
| 文件超大 | 同步 | 返回 400 | 提示文件过大 |
| 速率限制 | 同步 | 返回 429 | 请求过于频繁 |
| OSS 上传失败 | 同步 | 返回 503 | 系统繁忙 |
| ASR  失败 | 异步 | 重试 3 次，失败设为 failed | 轮询时显示失败 |
| LLM  失败 | 异步 | 使用 fallback 回复 | 返回预设回复 |
| TTS  失败 | 异步 | 重试 2 次，失败仅返回文本 | 有文本但无语音 |
| 数据库失败 | 异步 | 重试 3 次，记录日志 | 对用户无影响 |

## 二、接口：GET /api/v1/chat/result/{task_id}

**功能**：客户端轮询查询语音对话的处理结果

**流程类型**：同步查询

---

### 2.1 伪代码流程

```
流程：GET /api/v1/chat/result/{task_id}
├─ 【同步阶段】
│  │
│  ├─ 步骤 1：接收 HTTP 请求
│  │  ├─ 路径参数：task_id（字符串）
│  │  └─ 异常点：task_id 为空 → 返回 400 Bad Request
│  │
│  ├─ 步骤 2：身份验证
│  │  ├─ 从 HTTP Header 获取 Authorization Token
│  │  ├─ 调用 TokenService.ValidateToken(token)
│  │  └─ 异常点：Token 无效或过期 → 返回 401 Unauthorized
│  │
│  ├─ 步骤 3：提取用户 ID
│  │  ├─ user_id = Token.解析并获取(user_id)
│  │  └─ 异常点：Token 中缺少 user_id → 返回 401
│  │
│  ├─ 步骤 4：路径参数校验
│  │  ├─ 检查 task_id 格式（应该是 chat_{time.Now().UnixNano()}）
│  │  └─ 异常点：格式不合法 → 返回 400
│  │
│  ├─ 步骤 5：从 Redis 缓存查询任务状态
│  │  ├─ 调用 Cache.GetTaskStatus(task_id)
│  │  ├─ 返回：任务对象（包含 status、AI语音对话结果的缓存key）
│  │  └─ 异常点：
│  │     ├─ Redis 连接失败 → 降级到数据库查询
│  │     └─ 任务不存在于缓存 → 继续步骤 6
│  │
│  ├─ 步骤 6：权限检查（防止用户查询他人的任务）
│  │  ├─ 如果任务不存在于缓存：
│  │  │  ├─ 调用 Database.GetTaskByID(task_id)
│  │  │  ├─ 检查 task.user_id == 当前登录用户的 user_id
│  │  │  └─ 异常点：
│  │  │     ├─ 任务不存在 → 返回 404 Not Found
│  │  │     └─ user_id 不匹配 → 返回 403 Forbidden
│  │  └─ 如果存在于缓存：
│  │     └─ 权限已在缓存中验证，继续
│  │
│  ├─ 步骤 7：根据任务状态返回不同的响应
│  │  │
│  │  ├─ 【情况 A】：status == "pending"（任务等待中）
│  │  │  ├─ 返回响应体：
│  │  │  │  ├─ code = 200
│  │  │  │  ├─ message = "pending"
│  │  │  │  └─ data = {
│  │  │  │      task_id,
│  │  │  │      status: "pending",
│  │  │  │      current_stage: "queued",
│  │  │  │      message: "任务已进入队列，等待处理"
│  │  │  │    }
│  │  │  └─ HTTP 状态码：200 OK
│  │  │
│  │  ├─ 【情况 B】：status == "processing"（任务处理中）
│  │  │  ├─ 返回响应体：
│  │  │  │  ├─ code = 200
│  │  │  │  ├─ message = "processing"
│  │  │  │  └─ data = {
│  │  │  │      task_id,
│  │  │  │      status: "processing",
│  │  │  │      current_stage: (从任务对象获取，如 "asr" / "llm" / "tts"),
│  │  │  │      message: (对应阶段的描述，如 "正在识别语音...")
│  │  │  │    }
│  │  │  └─ HTTP 状态码：200 OK
│  │  │
│  │  ├─ 【情况 C】：status == "success"（任务完成成功）
│  │  │  ├─ 从缓存中获取AI语音对话结果：
│  │  │  │  ├─ 调用 Cache.Get(任务对象.ai_response_cache_key)
│  │  │  │  ├─ 返回：包含 AI 语音对话结果的 JSON 字符串
│  │  │  │  └─ 异常点：缓存键不存在 → 返回 500 Internal Server Error
│  │  │  ├─ 构建完整响应数据：
│  │  │  │  ├─ user_input = {
│  │  │  │  │  ├─ text: (从任务对象获取),
│  │  │  │  │  └─ duration_ms: (计算 end_time - start_time)
│  │  │  │  │}
│  │  │  │  ├─ ai_response = {
│  │  │  │  │  ├─ text: (从任务对象获取),
│  │  │  │  │  ├─ audio_url: (从任务对象获取),
│  │  │  │  │  └─ duration_ms: (计算语音时长)
│  │  │  │  │}
│  │  │  │  ├─ created_at: (任务创建时间),
│  │  │  │  └─ feedback_url: "/api/v1/chat/feedback"
│  │  │  ├─ 返回响应体：
│  │  │  │  ├─ code = 200
│  │  │  │  ├─ message = "success"
│  │  │  │  └─ data = {
│  │  │  │      task_id,
│  │  │  │      status: "success",
│  │  │  │      session_id: (从任务对象获取),
│  │  │  │      user_input,
│  │  │  │      ai_response,
│  │  │  │      created_at,
│  │  │  │      feedback_url
│  │  │  │    }
│  │  │  └─ HTTP 状态码：200 OK
│  │  │
│  │  ├─ 【情况 D】：status == "failed"（任务失败）
│  │  │  ├─ 从任务对象获取错误信息：
│  │  │  │  ├─ error_stage: (失败的阶段，如 "asr" / "llm" / "tts"),
│  │  │  │  └─ error_message: (具体错误描述)
│  │  │  ├─ 返回响应体：
│  │  │  │  ├─ code = 200
│  │  │  │  ├─ message = "failed"
│  │  │  │  └─ data = {
│  │  │  │      task_id,
│  │  │  │      status: "failed",
│  │  │  │      error_stage,
│  │  │  │      error_message,
│  │  │  │      message: "任务处理失败，请重试或联系支持"
│  │  │  │    }
│  │  │  └─ HTTP 状态码：200 OK
│  │  │
│  │  └─ 【其他情况】：未知的状态
│  │     ├─ 记录错误日志
│  │     └─ 返回 500 Internal Server Error
│  │
│  ├─ 步骤 8：更新 Token 有效期（可选优化）
│  │  ├─ 如果距离上次刷新时间 > 1 小时
│  │  │  └─ 调用 Cache.RefreshTokenTTL(user_id)
│  │  └─ 异常处理：刷新失败 → 继续（不影响响应）
│  │
│  └─ 步骤 9：返回响应
│     └─ 返回 JSON 响应给客户端
│
└─ 流程结束
```

### 2.2 异常处理总结

| 异常点 | 处理方式 | 用户感知 |

## 三、接口：GET /api/v1/chat/history/{session_id}

## 四、接口：DELETE /api/v1/chat/session/{session_id}

**功能**：删除指定会话及其所有对话记录

### 4.1 伪代码流程

```

│  ├─ 步骤 1：接收 HTTP 请求
│  │  ├─ 路径参数：session_id（字符串）

│  │
│  ├─ 步骤 4：路径参数校验

│  │  └─ 异常点：格式不合法 → 返回 400
│  │

│  │  ├─ 异常点：
│  │  │  ├─ 会话不存在 → 返回 404 Not Found
│  │  │  └─ session.user_id != 当前用户 ID → 返回 403 Forbidden
│  │  └─ 获取会话信息（用于统计和日志）
│  │
│  ├─ 步骤 6：删除 Redis 中的会话相关缓存（让前端立刻“看不到”会话）

│  │  │  ├─ user_id
│  │  │  ├─ session_id
│  │  │  └─ requested_at（时间戳）
│  │  ├─ 调用 Redis.XAdd(stream_key, fields)
│  │  └─ 异常处理：写入失败 → 记录错误日志，但仍然继续（缓存已删除，前端已无感知）

│  ├─ 步骤 8：构建响应体（删除请求已受理）

│  │

│  │  ├─ 消费组：group = "chat_delete_group"

│  │  ├─ 调用 Database.BeginTransaction()

│  │  ├─ 调用 Database.DeleteChatRecordsBySessionID(session_id)

│  │
│  ├─ 步骤 A6：删除数据库中的会话记录
│  │  ├─ 调用 Database.DeleteSession(session_id)
│  │  └─ 异常点：删除失败 → 回滚事务，记录日志，稍后重试
│  │
│  ├─ 步骤 A7：提交事务
│  │  ├─ 调用 Database.CommitTransaction()
│  │  └─ 异常点：提交失败 → 回滚，记录日志，稍后重试
│  │
│  ├─ 步骤 A8：删除 OSS 中的音频文件（最终一致性）
│  │  ├─ 对每个 audio_url：
│  │  │  ├─ 调用 OSS.DeleteObject(url)
│  │  │  └─ 异常处理：删除失败 → 重试 3 次，最终记录日志

│  │

│  │  └─ 异常处理：ACK 失败 → 记录日志，后续由回补机制重新处理

│  └─ 异步清理流程结束（最终一致）
│
└─ 流程结束
```

### 4.2 同步/异步职责说明

```
同步阶段（HTTP Handler 内）：
├─ 校验权限（GetSession 校验 user_id）
├─ 删除 Redis 缓存：
│  ├─ chat:session:{conversation_id}
│  └─ chat:history:{user_id}:{page}
├─ 向 Redis Stream 写入删除任务：
│  └─ XADD chat:delete_session * user_id=xxx session_id=yyy
└─ 返回 200 响应给前端（会话在 UI 上立即消失）

异步阶段（Worker 消费 Redis Stream）：
├─ XREADGROUP 从 chat:delete_session 读取消息
├─ 在事务中删除数据库记录：
│  ├─ DeleteChatRecordsBySessionID(session_id)
│  └─ DeleteSession(session_id)
├─ 删除 OSS 音频文件
├─ 更新用户统计信息
└─ XACK chat:delete_session message_id
```

**为什么这样设计？**
- 删除场景对“实时性”的感知主要来自前端列表；先删缓存即可让会话立即从 UI 中消失
- Redis Stream 作为轻量级队列，保证删除任务不会丢失，并支持失败重试与回补
- 数据库和 OSS 删除采用最终一致性模型，即使短暂失败也可以通过重试机制在后台完成
- 同步阶段逻辑轻量，不依赖事务，接口响应更快，整体用户体验更好

| 异常点 | 处理方式 | 用户感知 |
|--------|---------|---------|
| session_id 为空 | 返回 400 | 参数错误 |
| Token 过期 | 返回 401 | 需要重新登录 |
| session_id 格式错误 | 返回 400 | 参数错误 |
| 会话不存在 | 返回 404 | 会话不存在 |
| 权限不匹配 | 返回 403 | 无权限访问 |
| Redis Stream 写入失败 | 记录日志，继续 | 用户无感知（缓存已删除，会话已消失） |
| 事务启动失败（异步） | 记录日志，稍后重试 | 用户无感知 |
| 数据库删除失败（异步） | 回滚事务，记录日志，重试 | 用户无感知 |
| 事务提交失败（异步） | 回滚事务，记录日志，重试 | 用户无感知 |
| OSS 删除失败 | 重试 3 次，记录日志 | 用户无感知 |
| 缓存删除失败 | 记录日志，继续 | 用户无感知 |

│  │  │  ├─ last_message（最后一条消息的用户文本或 AI 回复）
│  │  │  └─ message_count（该会话中的消息总数）
│  │  └─ 异常点：数据库查询失败 → 返回 500
│  │
│  ├─ 步骤 8：对每条会话进行丰富化处理
│  │  ├─ 对每个 session：
│  │  │  ├─ 步骤 8.1：验证会话是否有效
│  │  │  │  └─ 检查 last_interaction_at 是否在过去 90 天内
│  │  │  │     └─ 如果否，可选：标记为 "inactive" 或过滤掉
│  │  │  │

│  │  │  │  ├─ 调用 Database.GetLastChatRecord(session_id)
│  │  │  │  ├─ 获取完整的消息内容
│  │  │  │  └─ 异常处理：查询失败 → 使用缓存的 last_message
│  │  │  │
│  │  │  ├─ 步骤 8.3：检查会话中是否有未读反馈
│  │  │  │  ├─ 调用 Database.HasUnreadFeedback(session_id)
│  │  │  │  ├─ 返回：unread_feedback_count

│  │  │  │
│  │  │  └─ 步骤 8.4：计算会话统计（可选优化）
│  │  │     ├─ 如果已在查询步骤 7 中包含 message_count → 跳过
│  │  │     └─ 否则调用 Database.CountChatRecords(session_id)
│  │  │
│  │  └─ 继续下一个会话
│  │
│  ├─ 步骤 9：构建响应数据
│  │  ├─ 对于每个会话，构建响应对象：
│  │  │  ├─ session_id
│  │  │  ├─ created_at
│  │  │  ├─ last_message（截断为 50 字符，含 ... 标记）
│  │  │  ├─ message_count
│  │  │  ├─ last_interaction_at
│  │  │  └─ unread_feedback_count（可选）
│  │  └─ 将所有会话对象收集到 items 数组
│  │
│  ├─ 步骤 10：排序验证
│  │  ├─ 验证会话列表按 last_interaction_at 降序排列（最近的在前）

│  │
│  ├─ 步骤 11：构建分页响应体
│  │  ├─ 响应结构：

│  │  │  ├─ 将结果缓存到 Redis

## 七、关键设计决策说明

### 7.1 为什么 POST /chat/submit 采用异步处理？

**原因**：
1. **避免超时**：ASR (30s) + LLM (30s) + TTS (20s) = 可能 80+ 秒，超过 HTTP 超时
2. **提高并发**：不占用 HTTP 连接，可处理更多并发请求
3. **改善用户体验**：立即返回任务 ID，不需要等待整个流程完成
4. **可重试**：异步任务失败可自动重试，不需要客户端重新上传音频

### 7.2 为什么 DELETE /chat/session 需要事务？

**原因**：
1. **数据一致性**：确保会话和其对话记录要么全部删除，要么全部保留
2. **防止脏数据**：如果删除会话成功但删除记录失败，会导致孤立记录
3. **原子性**：从用户角度，删除操作要么完全成功，要么完全失败

### 7.3 为什么要检查权限（user_id 匹配）？

**原因**：
1. **安全性**：防止用户 A 查询或删除用户 B 的数据
2. **访问控制**：确保数据隔离
3. **审计**：跟踪谁删除了什么数据

### 7.4 为什么 GET /chat/history 和 GET /chat/sessions 有缓存？

**原因**：
1. **性能**：列表查询通常不涉及实时性很强的数据
2. **降低数据库压力**：热点查询（page=1）可被缓存
3. **可接受的延迟**：5 分钟内的数据差异通常可接受
4. **缓存失效机制**：当新增/删除会话或消息时，主动清除缓存
