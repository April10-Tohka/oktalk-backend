```go
// ---- 以下方法供 report worker 使用 ----

// CountEvaluations 统计用户本周发音评测次数
// SELECT COUNT(*) FROM pronunciation_records WHERE user_id=? AND created_at BETWEEN ? AND ?
CountEvaluations(ctx context.Context, userID string, start, end time.Time) (int, error)

// CountConversations 统计用户本周场景对话次数（scene_messages 总条数）
// SELECT COUNT(*) FROM scene_messages WHERE user_id=? AND created_at BETWEEN ? AND ?
CountConversations(ctx context.Context, userID string, start, end time.Time) (int, error)

// CountPersistenceDays 统计用户本周有练习记录的天数（两表 created_at 取并集）
// 实现：
//   SELECT COUNT(DISTINCT DATE(created_at)) FROM (
//     SELECT created_at FROM pronunciation_records WHERE user_id=? AND created_at BETWEEN ? AND ?
//     UNION
//     SELECT created_at FROM scene_messages WHERE user_id=? AND created_at BETWEEN ? AND ?
//   ) t
CountPersistenceDays(ctx context.Context, userID string, start, end time.Time) (int, error)

// GetRadarScores 查询本周雷达图三个维度的平均分
// SELECT AVG(raw_score), AVG(fluency), AVG(integrity)
// FROM pronunciation_records WHERE user_id=? AND created_at BETWEEN ? AND ?
// 无记录时三个值均返回 0
GetRadarScores(ctx context.Context, userID string, start, end time.Time) (avgRaw, avgFluency, avgIntegrity float32, err error)

// GetHardWords 查询本周高频难词
// 查本周所有 pronunciation_records 的 problem_words 字段（JSON数组）
// 展开所有词，统计每个词出现次数，按频率降序取前 4 个
// 实现思路：
//   1. 查出本周所有 problem_words 字段值（JSON 字符串）
//   2. 在 Go 层 json.Unmarshal 每个值得到 []string
//   3. 用 map[string]int 统计词频
//   4. 排序后取前 4 个
//   5. 返回 []HardWord{ Word string, Count int }
GetHardWords(ctx context.Context, userID string, start, end time.Time) ([]HardWord, error)

// HardWord 难词统计结果
type HardWord struct {
    Word  string
    Count int
}
```

## 六、GenerateReport Service 修改

在现有 `GenerateReport` 函数中，修改**周期计算逻辑**：

```go
// 以本周一 00:00:00 为起点，本周日 23:59:59 为终点
// 注意：Go 的 time.Weekday() 中 Sunday=0，需要特殊处理
now := time.Now()
weekday := int(now.Weekday())
if weekday == 0 {
    weekday = 7 // 将 Sunday 从 0 改为 7
}
// 本周一
periodStart = time.Date(now.Year(), now.Month(), now.Day()-weekday+1,
    0, 0, 0, 0, now.Location())
// 本周日
periodEnd = time.Date(now.Year(), now.Month(), now.Day()-weekday+7,
    23, 59, 59, 999999999, now.Location())
```

同时修改数据量检查逻辑，改为查两张表：

```go
// 原来只查 pronunciation_records，现在要同时查 scene_messages
evalCount, _ := s.repos.LearningReport.CountEvaluations(ctx, req.UserID, periodStart, periodEnd)

    return "", fmt.Errorf("本周学习记录不足，至少需要 3 条（当前 %d 条）", evalCount+convCount)
```

## 九、代码约束

1. **最小改动原则**：只在标注位置新增代码，不重构现有逻辑，不移动现有代码
2. **pronunciation_record 字段写入**：只在发音评测 Service 创建记录的地方补充三个新字段，其他地方不改
3. **统计查询方法放在 LearningReportRepository**：不新建 Repository 文件，所有统计方法都加在现有报告 Repository 接口里
4. **难词 audio_url 查询**：通过 `PronunciationLoader` 遍历配置查找，找不到时 audio_url 返回空字符串，不报错
5. **LLM 输出解析要有 fallback**：JSON 解析失败时使用预设 fallback，不让解析错误中断 Worker 流程
6. **Worker 步骤失败处理**：LLM 调用失败时使用 fallback 继续，不把整个任务标记为 failed；只有数据库写入失败才标记 failed
7. **雷达图分数 clamp**：换算后的百分制分数必须 clamp 到 \[0, 100\]，不能超出范围
8. **周期计算时区**：使用 `time.Now()` 的本地时区，不硬编码 UTC
